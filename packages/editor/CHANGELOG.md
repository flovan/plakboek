# @plakboek/editor

## 0.6.0

### Minor Changes

- [#20](https://github.com/flovan/plakboek/pull/20) [`f1f3c8b`](https://github.com/flovan/plakboek/commit/f1f3c8b7dcf8eb7b86d1e8765d83d84417d5e989) Thanks [@flovan](https://github.com/flovan)! - Adds `createCmsPages`, the handler behind the admin entry under `/cms`. `/cms` shows the real page, blurred, inert and hidden from assistive technology in a same-origin iframe, with the sign-in card in a native dialog painted from declarative shadow DOM, so it is there at first paint without any script. `?next=` is accepted only as a path on this site. A valid session goes straight to the page in edit mode; a role that still has to set up two-step sign-in is sent to `/cms/two-factor/enrol`. The set-password, reset-password and sign-in-link landings, an invalid-link step shared by expired, used and malformed links, and the confirm step of two-step set-up are served at `/cms/set-password`, `/cms/reset-password`, `/cms/magic-link` and `/cms/two-factor/enrol`. A link's token is never written into the page, and the document sends no referrer.

- [#20](https://github.com/flovan/plakboek/pull/20) [`0bb4052`](https://github.com/flovan/plakboek/commit/0bb40520d7cecc4f391d6d69b7f7c6ff73a5605a) Thanks [@flovan](https://github.com/flovan)! - Adds the editor's server entry behind the visitor handler's `_edit` seam. `createEditEntrypoint(deps)` answers `<page>?_edit=1` with the edit shell, an editor-owned document whose declarative shadow root holds the chrome (sidebar and stage) and one same-origin iframe used as a viewport, and `<page>?_edit=frame` with the page itself: the host's own `renderDocument` called with mode `edit` for the live working tree, with the live `data-pk-*` attributes on every block. Every request re-reads the session, the two-factor gate and the role on the server: without a session the entrypoint answers `null` (the handler bounces to the plain page), an unenrolled superadmin is sent to `/cms/two-factor/enrol`, and a signed-in user without `pages:edit` gets a read-only shell whose frame shows the working tree with `pages:read-drafts` and the published page otherwise. Shell and frame responses carry `X-Robots-Tag: noindex, nofollow`; the shell sends a hash-based Content-Security-Policy and is never frameable, the frame only by its own origin. `bootEditor()` on the client entry hydrates the shell without reloading the frame, and the `SidebarSlots` type describes the sidebar's navigation slot. New exported types `EditEntrypointDeps`, `EditorAssets` and `EditorDevScript`.

- [#20](https://github.com/flovan/plakboek/pull/20) [`2dca895`](https://github.com/flovan/plakboek/commit/2dca895f313a437b717f721f3b625d48db473baf) Thanks [@flovan](https://github.com/flovan)! - Every emailed-link step of the sign-in modal now works. "Forgot your password?" and "Email me a sign-in link" open request steps that answer with one "Check your email" state whether or not the address has an account, keep the page the editor came from, and show "Too many attempts" when the server rate limits. The invitation and reset links land on their modal step, take the token out of the address bar and the browser history as soon as the page loads, set the new password through the single-use flow and return to sign-in with a status line. A sign-in link lands on "Signing you in" and runs the same hand-over into edit mode as a password sign-in. Expired, used and malformed links share one "This link is no longer valid" step whose button leads to the request that can replace the link. The sign-in-link step says that accounts using an authenticator app cannot use sign-in links, without saying anything about a given address. A sign-in link the service could not turn into a session, which is what happens to an account with two-step sign-in, lands on "This link could not sign you in" and points to password and code instead.

- [#20](https://github.com/flovan/plakboek/pull/20) [`47cf85f`](https://github.com/flovan/plakboek/commit/47cf85f6cf7d0a7589d2876d8cfc96da655d214a) Thanks [@flovan](https://github.com/flovan)! - The login card now works. Hydrated, it becomes a true modal over the blurred page: focus stays in the card, the site behind it gets no pointer or keyboard input, and Escape does nothing. Signing in checks the address and password before sending anything, shows problems under their field, and shows a refused or failed request in one alert box that takes focus. The password is cleared and the address kept, nothing says which of the two was wrong, and a second submit is ignored while one is in flight. A user with two-step sign-in goes on to the authenticator step, can ask for a code by email instead or sign in with one of the backup codes saved at set-up (each works once), and lands on a lockout step after five wrong codes or when the account is locked; a role that must set up two-step sign-in is sent to `/cms/two-factor/enrol`. A correct sign-in hands the blurred page over to the framed shell: the card fades, the page unblurs, the real frame shrinks to the right into the place the shell paints it and the sidebar slides in, all at 1:1 and within 600ms, then the editor flag is set and the page opens in edit mode. The target follows the layout last chosen (framed or full width); under reduced motion nothing moves, and a slow answer shows a spinner in the frame's place. The sign-in client loads on first use as its own chunk and only the auth library's browser client is used.

- [#20](https://github.com/flovan/plakboek/pull/20) [`e97202b`](https://github.com/flovan/plakboek/commit/e97202bbac0cfa67e1f83d65c2261b0b53b40e53) Thanks [@flovan](https://github.com/flovan)! - The edit shell now outlines the block under the pointer in the framed site. A 2px outline with a 1px halo is drawn exactly over the block's box, with a label chip carrying the block's editor label (or its type key; `{type} (unavailable)` for a block the host no longer declares), and a 1px dashed outline for the section around it. Everything is drawn in a layer of the shell, clipped to the frame, and nothing is added to the site's own document. The outline follows its block through scrolling, window resizes, the layout toggle and changes to the page, is updated at most once per animation frame, and clicks, keys and scrolling pass through to the site untouched. A read-only session gets no overlay.

- [#20](https://github.com/flovan/plakboek/pull/20) [`26e4e6d`](https://github.com/flovan/plakboek/commit/26e4e6d261ee3479aae9e7f0f6f0899f62fb4445) Thanks [@flovan](https://github.com/flovan)! - New package: the on-page editing chrome. This first release ships the package shell with a `./server` and a `./client` entry and the chrome's own precompiled stylesheet, built with Tailwind v4 for shadow roots, sized in px only and free of `@property` rules. `chromeStyleSheet(doc)` and `adoptChromeStyles(shadowRoot)` deliver it on the client, `chromeStyleElement()` and `CHROME_STYLE_CSP_HASH` deliver it as first-paint markup for hosts with a strict `style-src`.

- [#20](https://github.com/flovan/plakboek/pull/20) [`9d589ed`](https://github.com/flovan/plakboek/commit/9d589eda746b0666d0e43915df57c6fc4d4aef18) Thanks [@flovan](https://github.com/flovan)! - Gives the edit shell its behaviour. The shell opens framed and a Full width toggle switches to a 56px rail with the page flush; the choice is kept per browser and applied before first paint by a constant, hash-allowed inline script, so the framed layout never flashes. The rail carries the toggle, Exit edit mode, an avatar and Log out as icon buttons with CSS tooltips. Switching layouts moves keyboard focus to the toggle of the layout now shown, so it never rests on a hidden control. A link to another page of the site, clicked in the frame, navigates the whole page in edit mode; a link to another site, to a file of the site or to a `/cms` or `/api` route opens in a new tab with `noopener`; a link to the page already shown reloads the frame; same-page links, downloads, named targets and modified clicks keep the browser's behaviour, and a click the site's own script handled is left alone. A frame navigated by a script or a form is followed by the whole page. Below 1024px the frame is replaced by a panel asking for a wider window, and a page whose edit render fails shows a panel with a Reload page button and no error detail. The shell's title follows the page's, and Log out clears the editor flag in the browser.

- [#20](https://github.com/flovan/plakboek/pull/20) [`c9938cd`](https://github.com/flovan/plakboek/commit/c9938cd3bc676d005d3083af49df8c6869022196) Thanks [@flovan](https://github.com/flovan)! - A superadmin, or any role that must use two-step sign-in, can now set it up inside the login modal at `/cms/two-factor/enrol`. The card asks for the password again, then shows the setup key in groups of four with a button to copy it and an `otpauth://` link that opens the authenticator app (no QR code), checks the first six-digit code, shows the backup codes once with a copy button, and hands over to the edit shell. A wrong password or a wrong code shows its message and keeps the step; five wrong codes end on the lockout step. The key and the backup codes exist only in the card's state while the step is on screen: they are never put in the address, the page data, the browser's storage or the console, and reloading the step starts it again. The gate is unchanged: until the first code is accepted, edit mode still redirects to the set-up. Once a key is confirmed, asking for another is refused by the auth service.
