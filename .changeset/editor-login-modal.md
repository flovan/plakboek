The login card now works. Hydrated, it becomes a true modal over the blurred page: focus stays in the card, the site behind it gets no pointer or keyboard input, and Escape does nothing. Signing in checks the address and password before sending anything, shows problems under their field, and shows a refused or failed request in one alert box that takes focus. The password is cleared and the address kept, nothing says which of the two was wrong, and a second submit is ignored while one is in flight. A user with two-step sign-in goes on to the authenticator step, can ask for a code by email instead or sign in with one of the backup codes saved at set-up (each works once), and lands on a lockout step after five wrong codes or when the account is locked; a role that must set up two-step sign-in is sent to `/cms/two-factor/enrol`. A correct sign-in hands the blurred page over to the framed shell: the card fades, the page unblurs, the real frame shrinks to the right into the place the shell paints it and the sidebar slides in, all at 1:1 and within 600ms, then the editor flag is set and the page opens in edit mode. The target follows the layout last chosen (framed or full width); under reduced motion nothing moves, and a slow answer shows a spinner in the frame's place. The sign-in client loads on first use as its own chunk and only the auth library's browser client is used.
