Adds the editor's server entry behind the visitor handler's `_edit` seam. `createEditEntrypoint(deps)` answers `<page>?_edit=1` with the edit shell, an editor-owned document whose declarative shadow root holds the chrome (sidebar and stage) and one same-origin iframe used as a viewport, and `<page>?_edit=frame` with the page itself: the host's own `renderDocument` called with mode `edit` for the live working tree, with the live `data-pk-*` attributes on every block. Every request re-reads the session, the two-factor gate and the role on the server: without a session the entrypoint answers `null` (the handler bounces to the plain page), an unenrolled superadmin is sent to `/cms/two-factor/enrol`, and a signed-in user without `pages:edit` gets a read-only shell whose frame shows the working tree with `pages:read-drafts` and the published page otherwise. Shell and frame responses carry `X-Robots-Tag: noindex, nofollow`; the shell sends a hash-based Content-Security-Policy and is never frameable, the frame only by its own origin. `bootEditor()` on the client entry hydrates the shell without reloading the frame, and the `SidebarSlots` type describes the sidebar's navigation slot. New exported types `EditEntrypointDeps`, `EditorAssets` and `EditorDevScript`.
